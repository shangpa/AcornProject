# ERD 정책 확정 필요사항

개발 후 ERD 변경을 줄이려면 보상 수치보다 저장 구조가 달라질 수 있는 정책 선택지를 먼저 확정해야 한다.

## 1. 문서 목적

이 문서는 개발 전에 확정해야 할 정책을 정리해 ERD 변경을 줄이기 위한 체크리스트다.

정책값 자체는 나중에 바꿀 수 있다. 하지만 종류, 상태, 이력, 관계, 제약조건은 개발 후 바꾸면 table, column, FK, UNIQUE, index 변경으로 이어질 수 있으므로 먼저 정해야 한다.

## 2. DB 영향 유형 기준

| 구분 | 지금 확정해야 함 | 나중에 바꿔도 ERD 영향 적음 |
| --- | --- | --- |
| 데이터 구조 | 테이블, 컬럼, 관계, 상태값, 이력 저장 여부 | 보상 포인트 수치, 쿠폰 이름, 등급 기준값 |
| 정책 종류 | 포인트 획득처/소비처, 쿠폰 유형, 챌린지 유형, 등급 체계 | 이벤트성 보상량, 기간, 표시 문구 |
| 상태 흐름 | 발급, 사용, 만료, 취소, 환불, 숨김, 삭제 같은 상태 | 관리자 운영 기준 |

| DB 영향 유형 | 의미 | 예시 |
| --- | --- | --- |
| 변경 없음 | 코드/운영 정책 또는 기존 데이터 값만 조정 | 보상 포인트 수량 변경 |
| 데이터 추가 | 기존 table에 row 추가 | `MEMBER_GRADE` 등급 row 추가 |
| 단순 속성 추가 | 기존 table에 column 추가 | `BOOK.rental_period_days` 추가 |
| 속성 의미 수정 | 기존 column의 산정 기준 또는 의미 변경 | `MEMBER.grade_id` 산정 기준 변경 |
| 상태값 추가 | 기존 type/status column의 허용값 추가 | `COUPON_USAGE.status = 'CANCELLED'` 추가 |
| 제약조건 변경 | UNIQUE, FK, CHECK, NOT NULL 변경 | 쿠폰 중복 사용 허용 시 UNIQUE 변경 |
| 관계 변경 | 기존 table 사이 FK 또는 대상 관계 추가/변경 | 쿠폰 대상 도서/카테고리 연결 |
| 신규 table 필요 | 새 정책 단위를 별도 table로 관리 | `COUPON_TARGET` 추가 |
| 이력 table 필요 | 변경/연장/제재/만료 같은 이력을 별도 저장 | `MEMBER_GRADE_HISTORY` 추가 |
| 인덱스 추가 | 조회/제한 조건을 DB에서 안정적으로 처리 | 희망도서 월 신청 제한용 index |
| 집계 구조 변경 | 통계/랭킹/기간별 집계 구조 변경 | 랭킹 table 추가 |

## 2.1 최종 확정 답변 요약

| 영역 | 확정 답변 |
| --- | --- |
| 회원 등급 | 결제 금액 기준으로 완전 변경, 유지/하락 구현, 누적 금액은 `PAYMENT` 실시간 계산, 등급 유지 종료일과 등급 산정 시작일은 `MEMBER`에 저장, 등급 변경 이력 table 미생성, 혜택은 DB 미관리, 등급 상승 조건 달성률(%) 표시 |
| 대여 | 반납/연체 없음, 연체료/연체 차감 포인트/쿠폰 삭제, 첫 읽기 시점을 `rental_start_at`으로 저장하고 읽기 전에는 `NULL`, 대여 상태값 추가, 읽기 종료 후 `READY`, 소장 기능은 별도 상태값으로 분리, 연장 이력 저장 안 함, `rental_end_at`만 갱신, 무료→유료 전환은 도서 정책 |
| 결제/환불 | 결제수단은 `CARD`만 유지, 쿠폰/포인트는 할인/차감 수단, 할인 전 금액 저장, 환불/취소/복구/실패 결제 미구현, `PAYMENT_RECOVERY` 삭제, 0원 결제도 `PAYMENT` 저장 |
| 포인트 | 결제 차감으로 변경, `POINT_HISTORY`에 `PAYMENT` FK 추가, `MEMBER.point_balance`를 추가하고 `POINT_HISTORY`와 같은 트랜잭션에서 갱신, 포인트 타입 확정, 리뷰 작성 포인트는 수정/복구 시 중복 지급 없음 |
| 쿠폰/출석 | 쿠폰 유효기간 2주, % 할인과 금액 할인 모두 지원, 100% 할인은 결제 금액 0원 처리, 출석은 시작일 기준 월말 또는 30일 연속 계산, 보상 받은 다음 달 초기화, 로그인 시 발급 |
| 챌린지/통계 | 챌린지는 일일/전체만 운영, 일일 챌린지와 출석체크는 별도, 전체 챌린지는 가입 이후 1회 달성, 관리자 통계 중 도서별 완독수/완독률만 조회 계산하고 나머지는 DB 저장, 결제 총액은 쿠폰/포인트 차감 후 카드 결제액, 나이대별 대여 현황은 회원 생년월일 기준으로 집계 |
| 리뷰/신고/제재 | 리뷰와 별점 table 분리, 회원 1명은 동일 책에 리뷰 1개/별점 1개만 가능, 리뷰/별점은 첫 읽기 시작 시점부터 작성 가능, 별점은 수정/삭제 불가 및 상태값 없음, 회원 대상 신고 삭제, 리뷰 신고를 회원 신고와 같은 제재 흐름으로 처리, 제재 이력 저장, 제재 기준은 DB 미저장, 관리자 제재 처리 누적 5회는 5일 대여 불가, 10회는 10일 대여 불가, 10회 초과는 탈퇴 상태로 처리 |
| 희망도서 | 후보 집계용 별도 table 생성, `BOOK_REQUEST.request_candidate_id` 추가, 정규화 칼럼 실제 추가, 신청자 수 저장, 중복 신청 방지 후 신청자 수 증가, 후보 상태와 신청 row 상태를 분리, ISBN은 도서 등록 시에만 사용 |
| 알림/공지 | 대여 만료 임박 알림은 대여 종료 1일 전과 마지막 페이지 미도달 기준, 공지 수정 시 알림 재발송 안 함, 한 달 이후 알림 물리 삭제, `NOTICE.notify_yn` 저장, 이벤트 알림은 공지로 처리하지 않음 |
| 도서/검색/추천/이벤트 | 검색 대상에 출판사 추가, 누적 대여 횟수/평점/리뷰 수는 `BOOK` column에 저장, 누적 대여 수는 결제 완료 시점 증가, 평점과 리뷰 수는 서로 별도 table 기준으로 실시간 갱신, 관리자는 서비스에 등록된 도서를 이벤트 도서 묶음으로 CRUD 가능, 도서관 API 갱신 방식은 보류 |

## 3. 기능별 정책 확정 현황  - 임의 작성 부분 → @

### 출처 표시 기준

- `[회의]`: 회의 이후 문서에 있던 원본 내용
- `[@]`: 회의 이후 문서에서 `[@]`로 표시된 임의 작성 내용
- `[추가]`: 회의 이후 문서에는 없고, 이후 논의하면서 추가·정리한 내용
- `[@+추가]`: `[@]` 내용이 이후 논의에서 보정·구체화된 내용

### 3.1 회원 / 인증 / 등급  (영석)

### 이미 ERD 반영된 사항

- 회원가입 시 생년월일은 필수다.
- 회원 상태는 `JOINED`, `SANCTIONED`, `WITHDRAWN`, `DEACTIVATED`를 사용한다.
- 회원 탈퇴/삭제는 물리 삭제하지 않는다.
- 로그인 후 비밀번호 변경은 현재 로그인 세션과 현재 비밀번호 확인으로 처리한다.
- 회원 등급은 결제 금액 기준으로 산정한다.
- 등급 변경 이력 table은 만들지 않는다.

### 추가로 확정해야 할 정책 (보류)

- `[회의]` 등급명(유지기간) : 씨앗  -> 새싹(1개월) -> 나무(3개월) -> 도토리(6개월)
- `[회의]` 등급 상승 기준 :  결제 금액  (1개월 누적)2만 원 ⇒ (3개월 누적)10 만원 ⇒ (6개월 누적) 70만원
- `[@]` 등급 상승 시 다음 등급 산정 결제 금액은 0원부터 다시 시작한다. 예: 2만원 결제 후 새싹 등급이 되면, 이후 나무 등급 승급에는 추가 10만원 결제가 필요하다.
- `[@+추가]` 등급 유지 조건 : 유지기간 안에 상승 기준의 10% 금액을 결제하면 유지기간 종료일을 1개월 연장한다. 조건 불만족 시 유지기간 종료 즉시 한 단계 하락한다.
- `[회의]` 등급 산정 시점 :  조건 달성 시 즉시
- `[@]` 등급별 혜택 (유지) : 기본 대여 기간 적용 / +1일 / +3일 / +5일
- `[@]` 등급별 혜택 (달성 시 1회성) : 없음 / 유료도서 10% 쿠폰 / 30% 쿠폰 / 100% 쿠폰
- `[추가]` 등급 결제 금액 누적은 `PAYMENT` 기준 실시간 계산으로 처리한다.
- `[추가]` 결제 금액 누적 기간은 결제 시작일 기준 현재 날짜까지로 계산한다.
- `[추가]` 등급 상승까지 조건 달성률(%)을 표시한다.
- `[추가]` 등급 유지 종료일은 `MEMBER`에 저장한다.
- `[추가]` 등급 산정 시작일은 `MEMBER`에 저장한다.
- `[추가]` 등급 유지 조건을 달성하면 기존 등급 유지 종료일에 1개월을 더한다.
- `[추가]` 등급 유지 기간이 끝났고 유지 조건을 달성하지 못하면 즉시 한 단계 하락한다.
- `[추가]` 하락 후에도 등급 산정 금액은 0원부터 다시 시작한다.
- `[추가]` 등급 상승 후 다음 등급으로 가기 위한 결제 금액도 0원부터 다시 시작한다.
- `[추가]` 등급 산정 결제 금액은 쿠폰/포인트 차감 후 카드 결제액 기준이다.
- `[회의]` 등급 변경 이력 table은 만들지 않는다.
- `[추가]` 등급별 혜택은 DB로 관리하지 않는다.

### ERD 미반영 또는 확인 필요한 사항

- 등급 상승까지 조건 달성률(%) 표시를 위해 실시간 계산 쿼리 또는 화면용 계산 규칙을 정의해야 한다.

### 정책 변경 시 DB 영향

| 결정 항목 | DB 영향 유형 | 변경 예시 |
| --- | --- | --- |
| 등급명 추가 | 데이터 추가 | `MEMBER_GRADE` row 추가 |
| 등급 혜택 DB 미관리 | 변경 없음 | 코드/운영 정책으로 처리 |
| 등급 변경 이력 미저장 | 변경 없음 | `MEMBER_GRADE_HISTORY` 만들지 않음 |
| 등급 하락 도입 | 속성 의미 수정 | `MEMBER.grade_id` 산정 기준 변경 |
| 등급 달성률 표시 | 변경 없음 | `PAYMENT` 실시간 집계로 계산 |
| 등급 유지 종료일 저장 | 단순 속성 추가 | `MEMBER.grade_expires_at` 추가 |
| 등급 산정 시작일 저장 | 단순 속성 추가 | `MEMBER.grade_payment_started_at` 추가 |

### 3.2 대여 / 반납 / 연체

### 이미 ERD 반영된 사항

- 무료 도서는 결제 없이 대여할 수 있다.
- 유료 도서는 카드 또는 쿠폰 결제 승인 성공 후 대여를 생성한다.
- 무료/유료 도서 모두 동시 대여 가능 인원 제한이 없다.
- 전자책 완독은 책의 마지막 페이지에 도달한 시점으로 판정한다.

### 추가로 확정해야 할 정책

- `[회의]` 유료 책 - 대부분  (소장 기능 추가) / 무료 책 - 이벤트, 소수의 책 몇권
- `[@]` 기본 대여 기간 - 유료 14일 고정 / 무료 7일
- `[회의]` 연장 가능 여부 : 가능 / 연장 시 결제 필요
- `[회의]` 자동 반납 여부 : 자동 반납
- `[회의]` 대여 연장 /소장  : 해당 기능 수행 시 결제 필요
- `[회의]` 반납, 연체가 없다. (기간 끝나면 자동 반납 개념)
- `[추가]` 연체료, 연체료 차감 포인트, 연체료 차감 쿠폰은 삭제한다.
- `[회의]` 무료 책 한 번 대여하고 연장 가능 (연장 시 결제 필요)
- `[@]` 무료 책 무한 대여 불가. 무료 책 대여 기간이 끝나면 유료 책으로 전환한다.
- `[회의]` 대여 기간 차감 기준 - 대여 후 읽기 시작한 후 차감
- `[추가]` `rental_start_at`은 첫 읽기 시작 시점으로 고정한다.
- `[추가]` 읽기 전에는 `rental_start_at`을 `NULL`로 둔다.
- `[추가]` 대여 상태값을 추가한다.
- `[추가]` 기간이 끝나면 `READY` 상태로 돌아가며, 유료책은 할인된 금액으로 다시 대여할 수 있다.
- `[추가]` `EXPIRED` 상태는 사용하지 않는다.
- `[추가]` 연장 이력은 저장하지 않고 `BOOK_RENTAL.rental_end_at`만 갱신한다.
- `[추가]` 소장 기능은 실제 구현하며 별도 상태값으로 분리한다.
- `[@+추가]` 무료 책에서 유료 책으로 전환되는 정책은 도서 정책으로 처리한다.

### ERD 미반영 또는 확인 필요한 사항

- 대여 상태값은 `READY`, `READING`, `OWNED` 기준으로 정리한다.

### 정책 변경 시 DB 영향

| 결정 항목 | DB 영향 유형 | 변경 예시 |
| --- | --- | --- |
| 대여 기간을 공통 정책으로 운영 | 변경 없음 | 코드/설정값으로 처리 |
| 도서별 대여 기간 운영 | 단순 속성 추가 | `BOOK.rental_period_days` 추가 |
| 연장 이력 미저장 | 변경 없음 | `BOOK_RENTAL.rental_end_at` 갱신 |
| 반납/연체 제거 | 속성 의미 수정 또는 상태값 정리 | 반납/연체 관련 상태와 정책 제거 |
| 소장 기능 구현 | 상태값 추가 | `BOOK_RENTAL.rental_status = 'OWNED'` |
| 첫 읽기 전 시작일 NULL | 속성 제약 변경 | `BOOK_RENTAL.rental_start_at NULL` 허용 |

### 3.3 결제 / 환불

### 이미 ERD 반영된 사항

- 결제는 성공 이력만 저장한다.
- 결제수단은 `CARD`, `COUPON`만 사용한다.

- `[@]` 리뷰 제재 이력은 저장한다.
- `[@]` 회원 대상 신고는 완전히 삭제한다.
- `[@]` 리뷰 신고는 회원 신고와 같은 제재 흐름으로 본다.
- `[@]` 신고된 리뷰 숨김 처리와 회원 제재 처리는 함께 판단한다.
- `[회의]` 신고 누적 기준, 자동 숨김 기준 db에 저장하지 않음
- `[@+추가]` 관리자 제재 처리 항목 5회 누적 시 5일간 대여 불가 제재를 적용한다.
- `[@+추가]` 관리자 제재 처리 항목 10회 누적 시 10일간 대여 불가 제재를 적용한다.
- `[@+추가]` 관리자 제재 처리 항목 10회 초과 시 회원 탈퇴 상태로 처리한다.
- `[추가]` 제재 기준은 DB에 저장하지 않고 코드/운영 정책으로 처리한다.
- `[추가]` 제재 상태 조회용 현재 제재 정보를 `MEMBER`에도 함께 둔다.
- `[추가]` 신고 누적 10회 이하 제재는 대여 불가 제재로 보고 비활성 상태로 처리한다.
- `[@+추가]` 회원 삭제는 물리 삭제가 아니라 탈퇴 상태 변경으로 처리한다.
- `[추가]` 대여 불가 상태는 회원 비활성 상태로 처리한다.

### ERD 미반영 또는 확인 필요한 사항

- 제재 이력은 저장한다.
- 신고 누적 기준과 자동 숨김 기준은 DB에 저장하지 않는다.

### 3.8 희망 도서 신청 (영석)

### 이미 ERD 반영된 사항

- 희망도서 신청과 관리자 승인/반려 프로세스를 DB에 저장한다.
- 희망도서 신청에는 제목, 저자, 출판사, 신청 사유를 저장한다.
- 승인 후 등록된 도서와 연결할 수 있다.

### 추가로 확정해야 할 정책 `[@]`

- `[@]` 신청 처리 단위 : 도서 단위 집계 처리
    - 희망도서 신청은 회원별 개별 처리 방식이 아니라, 동일 도서별로 신청 건수를 집계하여 관리한다.
    - 관리자는 "어떤 회원이 신청했는지"보다 "어떤 도서를 몇 명이 신청했는지"를 기준으로 신청 현황을 확인한다.
    - 동일 도서에 여러 회원이 신청하면 하나의 희망도서 후보에 신청 수가 누적된다.
- `[@]` 중복 신청 처리
    - 같은 회원은 같은 희망도서를 1회만 신청할 수 있다.
    - 같은 회원이 이미 신청한 도서를 다시 신청하면 중복 신청으로 처리하지 않고 기존 신청 내역을 안내한다.
    - 다른 회원이 같은 도서를 신청하는 것은 허용하며, 해당 도서의 신청 수만 증가한다.
- `[@]` 동일 도서 판단 기준
    - 기본적으로 제목 + 저자 + 출판사가 모두 같은 경우 동일 도서로 판단한다.
    - 띄어쓰기에 따라 달라지는 부분은 백엔드에서 모든 띄어쓰기를 없앤 후 같은지 판단 해서 처리
- `[@]` 관리자 희망도서 신청현황 조회 기준
    - 관리자 화면에서는 희망도서 후보 단위로 목록을 조회한다.
    - 조회 항목은 제목, 저자, 출판사, 신청자 수, 최초 신청일, 처리 상태를 기준으로 한다.
    - 해당 도서를 신청한 회원 목록을 상세 조회할 수 있다.
- `[@]` 승인 처리
    - 관리자가 직접 ISBN을 입력해서 도서 등록 시 사용
    - 관리자가 특정 희망도서를 승인하면 해당 도서를 신청한 모든 회원의 신청 상태를 일괄 승인 처리한다.
    - 승인된 희망도서는 신규 도서 등록 대상이 되며, 등록 완료 시 실제 도서 정보와 연결할 수 있다.
- `[@]` 반려 처리
    - 관리자가 특정 희망도서를 반려하면 해당 도서를 신청한 모든 회원의 신청 상태를 일괄 반려 처리한다.
    - 반려 시 반려 사유를 저장한다.(관리자 재량 , 반려 사유 유형 없음)

- `[@+추가]` db 변경 시 후보 집계용 별도 table을 생성하고, 개별 신청 table에는 정규화 칼럼을 실제 추가한다.
- `[추가]` 개별 신청 row에는 후보 table FK를 추가한다.

BOOK_REQUEST

- member_id
- request_title
- request_author
- request_publisher
- normalized_title
- normalized_author
- normalized_publisher
- request_status

UNIQUE(member_id, normalized_title, normalized_author, normalized_publisher)

BOOK_REQUEST_CANDIDATE

- request_candidate_id
- normalized_title
- normalized_author
- normalized_publisher
- request_count
- first_requested_at
- candidate_status

- `[@+추가]` 신청자 수는 후보 table에 저장한다.
- `[@+추가]` 신청자 수는 중복 신청 방지 후 증가시킨다.
- `[@+추가]` 승인/반려 시 해당 후보에 연결된 모든 개별 신청 상태를 함께 변경한다.
- `[추가]` 후보 상태가 승인 상태가 되면 후보 상태로 관리하고, 신청 row는 신청 상태만 관리한다.
- `[추가]` ISBN은 희망도서 신청 단계에 저장하지 않고 관리자가 도서 등록할 때만 사용한다.

### ERD 미반영 또는 확인 필요한 사항

- 같은 회원의 같은 희망도서 중복 신청은 DB 제약조건으로 막는다.
- 월 신청 횟수 제한은 현재 정책에 포함하지 않는다.

### 정책 변경 시 DB 영향

| 결정 항목 | DB 영향 유형 | 변경 예시 |
| --- | --- | --- |
| 중복 신청 허용 | 변경 없음 | 애플리케이션 정책 처리 |
| 같은 회원의 같은 도서 중복 금지 | 제약조건 변경 | composite UNIQUE 추가 |
| 후보 집계 table 생성 | 신규 table 필요 | `BOOK_REQUEST_CANDIDATE` 추가 |
| 후보 FK 연결 | 관계 변경 | `BOOK_REQUEST.request_candidate_id` 추가 |
| 신청자 수 저장 | 단순 속성 추가 | `BOOK_REQUEST_CANDIDATE.request_count` 추가 |
| 승인 후 도서 연결 | 변경 없음 | 기존 `approved_book_id` 활용 |

### 3.9 알림 / 공지 (영석)

### 이미 ERD 반영된 사항

- 알림은 유형, 제목, 연결 대상, 읽음 여부만 저장한다.
- 알림 본문과 채널별 발송 이력은 저장하지 않는다.
- 공지 본문은 `NOTICE.content`에 저장한다.

### 추가로 확정해야 할 정책

- `[회의]` 알림 발생 조건
    - `[@]` 대여: 대여기간 만료 임박 + 마지막 페이지 미도달 시
    - `[@]` 쿠폰: 발급 시
    - `[회의]` 이벤트(메인으로)
    - `[@]` 공지: 공지 등록 시
- `[@]` 대여기간 만료 임박 알림
    - `[@+추가]` 대여 기간 종료 1일 전이고 마지막 페이지 미도달 상태일 때 알림 생성
- `[@]` 공지 등록 알림
    - `[@]` 공지 등록 시 관리자가 회원 알림 생성 여부 결정 가능
    - `[@]` 공지 수정 시 알림 재발송 안 함
- `[회의]` 알림 제목 규칙
- `[회의]` 알림 보관 기간 : 한 달
- `[추가]` 한 달이 지난 알림은 물리 삭제 처리한다.
- `[회의]` 읽음 처리 기준 :
    - `[회의]` 알림 행 클릭 시 읽음
    - `[회의]` 알림 클릭  연결 화면으로 이동 시  읽음
    - `[회의]` 모두 읽음 버튼 클릭 시 읽음
- `[회의]` 채널별 알림 발송 이력 저장하지 않는다 ( 채널 : 알림을 보내는 경로 ex, 이메일,sns 문자, 카카오톡 등)
- `[회의]` 알림 본문은 저장하지 않
- `[추가]` 공지 알림 생성 여부는 `NOTICE.notify_yn`에 저장한다.
- `[추가]` 이벤트 알림은 공지로 처리하지 않는다.

### ERD 미반영 또는 확인 필요한 사항

- 알림 본문과 채널별 발송 이력은 저장하지 않는다.
- 이벤트 알림은 별도 알림 유형으로 처리한다.

### 정책 변경 시 DB 영향

| --- | --- | --- |

| 알림 보관 기간 정책 | 변경 없음 | 한 달 이후 물리 삭제 |
| 다형 target 유지 | 변경 없음 | 기존 `target_type`, `target_id` 활용 |
| 공지 알림 생성 여부 저장 | 단순 속성 추가 | `NOTICE.notify_yn` 추가 |
| 이벤트 알림 공지 미처리 | 상태값 추가 | `NOTIFICATION.notification_type = 'EVENT'` |

### 3.10 도서 / 분류/ 도서관 위 (영석)

### 이미 ERD 반영된 사항

- 전자책 서비스에서 책이 있는 도서관 위치만 제공한다.
- 도서관 좌표는 API로 받은 위도/경도를 저장할 수 있고 `NULL`을 허용한다.
- 추천은 같은 작가, 카테고리, 장르 키워드 기준의 단순 쿼리로 처리한다.
- 추천 로그는 저장하지 않는다.
- 장르 키워드와 해시태그는 책과 N:M으로 연결한다.

### 추가로 확정해야 할 정책

- `[회의]` 필터 기준 : 정렬
    - `[@]` 검색어 : 제목, 저자, 출판사
    - `[회의]` 카테고리 : 전체, 카테고리
    - `[@]` 인기순(누적 대여 횟수), 최신순(등록 순서), 제목 순(가나다), 평점 높은 순, 리뷰 개수 순
- `[회의]` 추천 기준 확장 여부 : 확장 안함
- `[회의]` 도서관 API 갱신 방식  : 보류
- `[회의]` 개인화 추천 여부 : 안함
- `[회의]` 장르 키워드/ 해시태그는 추천 기준에서 제외
- `[추가]` 누적 대여 횟수, 평점, 리뷰 수는 `BOOK` column에 저장한다.
- `[@+추가]` 누적 대여 횟수는 결제 완료 시점에 증가시킨다.
- `[추가]` 평점과 리뷰는 별도 table이므로 서로 독립적으로 집계한다.
- `[추가]` 리뷰 수는 `REVIEW.status = 'ACTIVE'`인 리뷰만 카운트한다.
- `[추가]` 도서 집계값은 전부 실시간 갱신한다.
- `[추가]` 관리자 이벤트 기능을 제공한다.
    - `[추가]` 이벤트는 관리자가 설정한 도서 목록이며, 도서 검색 필터만으로 처리하기 어려운 도서 묶음이다.
    - `[추가]` 예시는 무료 도서, 할인 도서, 관리자 추천 도서다.
    - `[추가]` 관리자는 관리자 페이지에서 이벤트를 생성, 조회, 수정, 삭제할 수 있다.
    - `[추가]` 이벤트에는 서비스에 이미 등록된 도서만 추가할 수 있고, 없는 도서는 추가할 수 없다.
    - `[추가]` 이벤트는 일시적인 도서 묶음이며 무료책 이벤트는 예외적으로 장기 운영할 수 있다.

### ERD 미반영 또는 확인 필요한 사항

- 추천 로그는 저장하지 않는다.
- 개인화 추천은 구현하지 않는다.

### 정책 변경 시 DB 영향

| 결정 항목 | DB 영향 유형 | 변경 예시 |
| --- | --- | --- |
| 추천 로그 저장 | 신규 table 필요 | `RECOMMENDATION_LOG` 추가 |
| 개인화 추천 | 신규 table 또는 관계 변경 | 사용자 선호 table 추가 |
| 필터 조건 추가 | 단순 속성 추가 또는 관계 변경 | 도서 속성/태그 확장 |
| 도서관 좌표 미확보 허용 | 변경 없음 | 기존 `NULL` 허용 유지 |
| 검색 대상 출판사 추가 | 인덱스 추가 | 출판사 검색 index 필요 가능 |
| 도서 집계값 저장 | 단순 속성 추가 | `BOOK.rental_count`, `BOOK.average_rating`, `BOOK.review_count` 추가 |
| 관리자 이벤트 도서 묶음 관리 | 신규 table 필요 | `EVENT`, `EVENT_BOOK` 추가 |

| 대여 | 읽기 전 시작일 NULL | `BOOK_RENTAL.rental_start_at NULL` 허용 |

| 포인트 | 결제 차감 연결 | `POINT_HISTORY.payment_id` |
| 쿠폰 | 쿠폰 유효기간 | `MEMBER_COUPON.expires_at` |

| 공지 | 공지 알림 생성 여부 | `NOTICE.notify_yn` |
| 도서 | 정렬/검색 집계값 | `BOOK.rental_count`, `BOOK.average_rating`, `BOOK.review_count` |

## 5. 개발 전 우선 결정 목록

| 우선순위 | 결정 항목 | 이유 |
| --- | --- | --- |
| 1 | 결제/환불 구조 정리 | `CARD`만 유지, 0원 결제 저장, `PAYMENT_RECOVERY` 제거 |
| 2 | 리뷰/별점 구조 변경 | `REVIEW.rental_id UNIQUE`에서 회원+도서 기준 및 `RATING` 분리로 변경 |
| 3 | 제재 이력 추가와 회원 신고 삭제 | `SANCTION_HISTORY` 추가, `USER_REPORT` 제거 |
| 4 | 희망도서 후보 집계 구조 추가 | `BOOK_REQUEST_CANDIDATE` 추가, 정규화 column과 신청자 수 저장 |
| 5 | 포인트 결제 차감 연결 | `POINT_HISTORY.payment_id` FK와 point_type 확정 |
| 6 | 도서 집계값 저장 | `BOOK.rental_count`, `average_rating`, `review_count` 추가 |
| 7 | 관리자 이벤트 도서 묶음 추가 | `EVENT`, `EVENT_BOOK`으로 관리자 설정 도서 목록 관리 |
| 8 | 나이대별 대여 현황 집계 | 생년월일 기준 계산 또는 관리자 통계 dimension 추가 필요 |
| 9 | 회원 등급 산정 기준 변경 | 결제 금액 실시간 계산, `MEMBER`에 등급 유지 종료일/산정 시작일 저장, 이력 table 미생성, 달성률 표시 |

## 결론

값은 나중에 바꿔도 되지만, 종류, 상태, 이력, 관계, 제약조건은 지금 확정해야 ERD가 바뀌지 않는다. 특히 신규 table, 상태값 추가, 제약조건 변경으로 이어질 정책은 개발 전에 먼저 결정해야 한다.
